# Systems Architecture & Distributed Engineering Playbook

## 1. Fundamentals of Distributed Systems
A distributed system consists of autonomous computing nodes that coordinate by exchanging messages over a network. Designing distributed infrastructure requires balancing trade-offs between consistency, availability, and partition tolerance, as formalized by the CAP theorem. In modern high-throughput architectures, systems frequently adopt PACELC formulations: if there is a partition (P), how does the system trade off availability (A) and consistency (C); else (E), how does it trade off latency (L) and consistency (C)?

## 2. Distributed Consensus: Raft vs. Paxos
Consensus protocols ensure that a cluster of machines agree on a sequence of state machine transitions despite network delays or node crashes.
- **Paxos:** Designed by Leslie Lamport, Paxos decouples consensus into proposer, acceptor, and learner roles. While mathematically elegant, multi-decree Paxos is notoriously difficult to implement in production software.
- **Raft:** Proposed by Ongaro and Ousterhout to improve understandability. Raft decomposes consensus into explicit leader election, log replication, and safety guarantees. A leader accepts client proposals, appends log entries, replicates them to a quorum of followers, and commits entries once acknowledged by a majority.

## 3. Data Partitioning & Consistent Hashing
When scaling stateful storage across dozens of nodes, data must be partitioned to prevent hotspots.
- **Range Partitioning:** Divides keys by contiguous ranges. While range queries become efficient, sequential write patterns can overwhelm a single partition.
- **Consistent Hashing:** Maps both server nodes and cache keys to a circular 128-bit or 256-bit hash ring. When a server joins or departs, only $K/N$ keys need to be migrated on average. Virtual nodes (vnodes) distribute keys uniformly across physical hardware with disparate compute capacities.

## 4. Storage Engines: LSM-Trees vs. B-Trees
Storage engines dictate disk I/O patterns, write amplification, and read latency.
- **B-Trees / B+ Trees:** Structure data as balanced hierarchical trees with fixed-size pages (e.g. 4KB or 8KB). Updates mutate pages in place, backed by a Write-Ahead Log (WAL). They deliver deterministic O(log N) point reads and range scans but suffer from write amplification due to random disk writes.
- **Log-Structured Merge-Trees (LSM):** Direct writes into an in-memory sorted buffer (MemTable) while appending to a WAL. When the MemTable reaches capacity, it flushes sequentially to disk as an immutable SSTable (Sorted String Table). Background compaction merges overlapping SSTables. LSM trees offer superior write throughput at the expense of read amplification, which is mitigated via Bloom filters.

## 5. Vector Database Architectures
Vector search engines index high-dimensional embeddings generated by deep learning models to perform similarity queries based on geometric proximity.
- **Brute-Force k-NN:** Evaluates exact distance across all $N$ vectors. Computation cost scales as $O(N \cdot D)$. Accurate but prohibitively slow for real-time queries over millions of vectors.
- **Inverted File Index (IVF):** Partitions vector space into Voronoi cells using k-means clustering. At query time, only vectors inside the nearest centroid cells are evaluated.
- **Hierarchical Navigable Small World (HNSW):** Constructs a multi-layer proximity graph where upper layers feature long-range skip connections and lower layers contain dense local connections. Traversal begins at top layers using greedy routing and finishes at layer 0 via beam search. HNSW achieves logarithmic search time with sub-10ms latency and high recall.
- **Product Quantization (PQ):** Decomposes high-dimensional vectors into orthogonal sub-vectors and quantizes each into centroid indices, reducing memory footprints by 8x to 16x.

## 6. Caching Strategies & Invalidation
Effective caching minimizes database load and stabilizes tail latencies.
- **Cache-Aside (Lazy Loading):** The application queries the cache first. On a cache miss, it reads from the primary store, populates the cache, and returns data to the client.
- **Write-Through:** Updates are written synchronously to the cache and the backing datastore. Ensures consistency but increases write latency.
- **Write-Behind (Write-Back):** Writes are acknowledged immediately to the client upon cache write, and flushed asynchronously to persistent storage in batches. Risk of data loss during server restarts.
- **Cache Invalidation:** As Phil Karlton noted, cache invalidation is one of computer science's hardest problems. Common solutions involve explicit TTL expirations, event-driven CDC (Change Data Capture) via Debezium, or cache stampede mitigation through probabilistic early expiration (XFetch).
